# 公民組織 GitHub 交流報名回覆整理

> 依講綱與活動目標整理交流需求及建議方向

## 一 活動目標與講綱對應

**整體交流應完成三件事：** 先讓非程式背景的參與者建立GitHub基本概念；再示範如何從組織需求搜尋、閱讀及初步判斷資源；最後說明GitHub可以提供工具、架構、流程、設計與公共利益專案的參考，但不會自動取代工作流程設計、資安判斷與後續維護。

| 講綱單元 | 回應報名需求的重點 | 與活動目標的連結 |
|----|----|----|
| 一 認識GitHub觀念與基本術語 | 釐清GitHub、Repository、開源、公開、免費及雲端服務的差異 | 降低名詞門檻並界定平台能做與不能做的事 |
| 二 導覽GitHub平台介面 | 認識搜尋、專案頁面、帳號與通知等基本入口 | 讓初學者知道到哪裡找資訊及如何回到專案 |
| 三 導覽Repository頁面 | 閱讀README、License、Releases、Issues、更新時間與資料夾 | 讓初學者知道如何「初步判斷專案」是否符合需求 |
| 四 練習平台搜尋功能及下載 | 把組織需求轉成資源類型與搜尋詞，再正確取得檔案 | 降低未來尋找與試用開源資源的門檻 |
| 五 AI協作資源判斷 | 用AI翻譯、摘要、比較與提出查核問題，並回查原始資料 | 讓AI成為理解橋樑 |
| 六 示範資料上傳至GitHub平台 | 認識版本、公開與私人權限及不可上傳的敏感內容 | 建立分享與協作想像，同時保留資料治理界線 |

## 二 逐題分類與交流方向

參與者對GitHub與開源資源的認識不一。部分回答可直接對應講座內容，但有部分回答是行政重複、資料分散、流程不順或想學AI等問題，則希望藉著講座與交流階段協助參與者釐清組織在什麼情況、什麼階段可以藉由GitHub取得幫助，哪些問題需要先進行工作流程的盤點設計，哪些問題才是能進一步轉換成GitHub上的資源類型或搜尋關鍵字。
