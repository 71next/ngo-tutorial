## 1. 課程定位

本課程不是 Git 指令課。目標是讓非技術背景的公民組織成員，只用瀏覽器就能在 GitHub 上找到、判斷、下載與分享開源資源。

**課程主線：**

```text
認識 GitHub 觀念與術語
→ 導覽平台介面與 Repository 頁面
→ 用六項健康檢查判斷專案能不能用
→ 練習搜尋、下載、上傳
→ 學會四種找資源的手法：搜尋語法、主題清單、順藤摸瓜、AI
→ 用 AI 找候選專案、讀懂專案，自己查證
→ 知道哪些資料不能放上 GitHub
```

**課程核心句：**

> 你想做的工具，很可能已經有人做好、免費公開了。
>
> AI 負責提名，你負責查證。

## 2. 目標對象

- 公民團體、非營利組織與基金會工作者，以非技術背景、初次接觸 GitHub 者為主。
- 形式：線上（視訊會議＋螢幕分享），講述 40%、實作 60%。
- 人數建議 15–30 人；超過 20 人建議安排 1 位助教看聊天室。
- 先備條件：會用瀏覽器、已註冊 GitHub 帳號。全程不安裝 Git、不寫程式。

## 3. 學習目標

課程結束後，學員能夠：

1. 用自己的話說明 Repository、README、Star、Fork、Release、License 的意思
2. 在 GitHub 用關鍵字加篩選條件（topic、stars、pushed、license、org）找到符合需求的專案
3. 用六項健康檢查判斷一個專案適不適合組織採用
4. 用 Releases、Download ZIP、Fork 取得資源，並在網頁上建立 Repo、上傳檔案
5. 用 AI 工具找候選專案、讀懂專案，並自行查證網址與授權
6. 說出哪些資料不該上傳到 GitHub，以及傳錯時該先做什麼

**本課程不承諾完成：**

- 教會 Git 指令與程式開發。
- 建置或部署任何系統。
- 保證某個 GitHub 專案安全、合法或適合直接導入。

## 4. 90 分鐘流程

| 時間 | 單元 | 形式 | 簡報頁 | 講義頁 |

| 05–20 | 一、GitHub 觀念與基本術語 | 講述＋比喻 | 4–5 | 2 |
| 20–35 | 二、導覽 GitHub 平台介面 | 螢幕示範 | 6 | 3 |

## 7. 授課前檢查

詳細清單見 [講師教案的「課前準備清單」](guide/README.md#課前準備清單)。另外：

- [ ] 簡報封面與講義最後一頁填入講師姓名、日期、主辦單位與聯絡方式。
- [ ] 授課前一週再檢查一次示範專案的 README、授權與連結（專案可能改版或封存）。
- [ ] 確認 GitHub Copilot 免費方案目前的對話額度（github.com/features/copilot/plans）。
- [ ] 決定上傳練習要請學員建 Private 還是 Public repo（目前教案與講義寫 Private）。
- [ ] 試講並計時，確保實作段落（50–85 分）有足夠時間。

## 8. （選用）公司與服務露出

新版簡報與講義目前沒有放入公司介紹；需要時可加在簡報第 19 頁與講義第 11 頁。

**建議定位：**

> 我們協助組織從工作流程與實際需求出發，評估合適的開源及數位工具，並規劃網站、資料整合、自動化與後續維護。

**露出方式：**

- 開場約 1 分鐘：介紹講師背景與平時協助組織解決的問題。
- 結尾約 2–3 分鐘：說明哪些問題可自行處理、哪些問題需要協助。
- 講義最後一頁：標示公司服務、聯絡方式及 QR code。

未確定實際交付範圍前，不在課堂承諾免費診斷、固定時數或特定成效。

## 9. 教材驗收標準

> 一位完全不會寫程式的參與者，在課後仍能拿著講義，用 GitHub 搜尋語法找到一個符合組織需求的專案，用六項健康檢查判斷它能不能用，選對方式把它下載回來，並且會用 AI 縮小範圍、自己回 GitHub 查證網址與授權。
