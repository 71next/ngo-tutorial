三、怎麼選 · 授權

常見授權一次看懂

授權類型公民組織要注意什麼
MIT寬鬆：可用、可改、可商用保留原作者的版權聲明與授權文字就好
Apache 2.0寬鬆：同 MIT，另含專利授權保留聲明（含 NOTICE 檔）；修改過的檔案要註明有改
GPL-3.0互惠：可用、可改、可商用把修改版「發給別人」時，要用同樣的 GPL 公開原始碼；只在組織內部使用不受影響
AGPL-3.0互惠：比 GPL 更嚴修改後放上網站讓別人使用，也要向使用者提供原始碼
CC 授權常用在文件、圖片、資料BY＝標示出處　NC＝不可商用　ND＝不可改作　SA＝改作要用相同授權；CC0＝放棄權利，可自由使用
沒有 License預設保留所有權利只能看、不能拿來改用或散布；想用請先寫信問作者，或找有授權的替代品

在 Repo 右側 About 下方，或檔案列表裡的 LICENSE 檔查看。看不懂可到 choosealicense.com 查（GitHub 官方的授權說明網站）。以上為簡化說明，正式採用前請懂授權的夥伴確認原文。

公民組織的 GitHub 資源搜索與選擇指南 · 10

重點只講兩件事：一、MIT、Apache 這類「寬鬆」授權，組織拿來用、改、甚至商用都可以，記得保留原作者聲明；二、GPL、AGPL 這類「互惠」授權也能用，但如果把修改後的版本發給別人（AGPL 連放上網站給人用也算），就要用同樣授權公開原始碼。只在組織內部自己用，通常不受影響。文件、圖片、資料常見 CC 授權，看縮寫：BY 標示出處、NC 不可商用、ND 不可改作、SA 相同方式分享。最後提醒：沒有 License 不等於免費，預設是作者保留所有權利。可以回頭對照第 8 頁截圖右側的「MIT license」。

Tag 與 Release 的差異

Tag（標籤）Release（發行版）
本質Git 裡指向某次 Commit 的書籤，只有程式碼建在 Tag 上的 GitHub 展示頁，含版本說明（Release Notes）、更新內容與致謝
附加檔案不能夾帶檔案可上傳打包好的安裝檔（.exe、.apk、.zip），不用架開發環境就能下載使用
在哪裡看藏在分支選單的 Tags 分頁或 Git 紀錄裡Repo 首頁右側 Releases，最顯眼

一句話：有 Tag 不一定有 Release；要下載軟體，看 Releases 就對了。

實作 5 分鐘：每人對剛剛收藏的專案試一次 Download ZIP，並找一個有 Releases 的專案看 Assets。點「Tag 跟 Release 有什麼不同？」開彈窗（Esc 或點外面關閉）：Tag 只是幫某次 Commit 貼上版本號（例如 v1.2.0）的書籤；Release 是 GitHub 在 Tag 上加的說明頁，可以附上安裝檔。提醒資安：只從可信任、星數與維護狀況良好的專案下載執行檔；下載後用防毒軟體掃描。

這些東西，不要放上 GitHub

類別例子為什麼
個資會員、志工、捐款人名單，個案資料，身分證字號、電話、地址Public 全世界看得到；Private 也可能因加錯協作者或誤設公開而外流
密碼與金鑰帳號密碼、API Key、Token、.env 設定檔有機器人隨時在掃描 GitHub，幾分鐘內就可能被盜用
內部文件合約、財報草稿、補助申請書、內部會議紀錄一公開就收不回來
沒有權利的素材別人的照片、付費圖庫、字型、新聞全文侵犯著作權，會被要求下架
大檔案影片、大量照片網頁上傳單檔上限 25MB；GitHub 不是雲端硬碟

刪掉不等於消失：Commit 歷史會留著舊版，別人也可能已經 Fork 走。傳錯了先換密碼、換金鑰，再處理檔案。

GitHub 使用規範禁止的行為

冒充他人假冒其他人、組織或品牌開帳號、發內容
騷擾與洗版在 Issue、討論區攻擊他人、重複張貼、打廣告
惡意或違法內容病毒、釣魚網頁、侵權檔案、違法內容
灌星與假帳號買 Star、用多個帳號互刷；一人只能有一個免費帳號
當成檔案分享站拿 GitHub 放影音、大量下載檔給大眾取用

違反規定，GitHub 可以隱藏內容、停用 Repo，甚至停權帳號。

接續剛才的提示詞練習也提醒一次：AI 推薦的網址與授權要自己回 GitHub 查證，提問時也不要貼會員名單等個資。這頁的重點是「上傳」：剛才第 14 頁建 Repo 時就要想好。最常見的意外是把含有密碼或 API Key 的設定檔、或是含個資的 Excel 傳上去；就算馬上刪掉，Commit 歷史裡還找得到，所以第一件事是換密碼、換金鑰。Private repo 適合放內部草稿，但不是保險箱，個資還是不要放。點「GitHub 禁止哪些行為？」開彈窗，依 GitHub Acceptable Use Policies 與服務條款整理，課前可再確認 docs.github.com/site-policy。
