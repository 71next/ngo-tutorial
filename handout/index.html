01十個一定會看到的詞

不需要背，先認得。找資源最常用的是 Repository、README、Star、Release、License 這五個。

英文中文白話解釋
Repository（Repo）儲存庫一個專案的資料夾，含所有檔案與修改紀錄
README說明文件專案首頁的說明書：做什麼、怎麼用
Commit提交一次存檔，附上「改了什麼」的說明
Branch分支平行的工作版本，改好再合併回主線
Fork分叉複製把別人的專案複製一份到自己帳號
Star星號收藏＋按讚，常被當作受歡迎程度
Issue議題回報問題、提出建議的討論串
Pull Request（PR）合併請求請原作者把你的修改合併進去
Release發行版打包好、可直接下載的正式版本
License授權條款決定你能不能用、能不能改、能不能商用

比喻把 GitHub 想成一座公共圖書館

Git＝版本管理工具

像文件的「修訂紀錄」，記下每一次誰改了什麼，隨時能回到舊版本。裝在電腦上使用。

GitHub＝線上平台

存放 Git 專案的雲端圖書館。每個 Repo 是一本書，README 是書的封底簡介，Star 是讀者評分。

GitHub 動作在圖書館裡就像……
Fork影印一本書帶回家，自己加註
Issue在圖書館意見箱留言
Pull Request寫信給作者：「我幫你改了錯字，要不要收進下一版？」
今天只用 GitHub 網頁，不需要安裝 Git。GitHub 沒有官方中文介面，可用瀏覽器右鍵「翻譯成中文」。

登入後右上角頭像選單：Your profile（個人頁）、Your repositories（我的專案）、Your stars（我收藏的專案）。

分頁用途
Topics最有用：依主題標籤列出同類專案

容易誤會：Marketplace

github.com/marketplace 是 GitHub 的外掛商店：Apps（接到 Repo 的第三方服務，如 Codecov）與 Actions（自動測試、自動部署）。

它不是開源軟體商店。要找志工、捐款等工具，請到 Repositories 用搜尋語法與 Topics 找。

04選用前的六項健康檢查

檢查項目去哪裡看參考標準
還有人維護檔案列表上方的最後 Commit 時間一年內有更新較安心
授權清楚右側 About 下方的 LicenseMIT、Apache、GPL 等（見下表）；沒標示＝不可隨意使用
說明完整README有用途、安裝、截圖或示範網址
有人使用右上角 Star、Fork 數只是參考，小眾專案也可能很好用
問題有回應Issues 分頁近期問題有作者回覆
能直接下載Releases有打包好的版本，非技術人員較易上手

授權常見授權一次看懂

授權類型公民組織要注意什麼
MIT寬鬆：可用、可改、可商用保留原作者的版權聲明與授權文字就好
Apache 2.0寬鬆：同 MIT，另含專利授權保留聲明（含 NOTICE 檔）；修改過的檔案要註明有改
GPL-3.0互惠：可用、可改、可商用把修改版「發給別人」時，要用同樣的 GPL 公開原始碼；只在組織內部使用不受影響
AGPL-3.0互惠：比 GPL 更嚴修改後放上網站讓別人使用，也要向使用者提供原始碼
CC 授權常用在文件、圖片、資料BY＝標示出處　NC＝不可商用　ND＝不可改作　SA＝改作要用相同授權；CC0＝放棄權利，可自由使用
沒有 License預設保留所有權利只能看、不能拿來改用或散布；想用請先寫信問作者，或找有授權的替代品
在 Repo 右側 About 下方，或檔案列表裡的 LICENSE 檔查看授權。看不懂可到 choosealicense.com 查（GitHub 官方的授權說明網站）。以上為簡化說明，組織正式採用前，請懂授權的夥伴確認原文。

06如何找 GitHub 上的資源：四種手法

GitHub 站內搜尋只比對名稱、說明和 README 的文字，不會猜你的需求；用英文關鍵字，結果最多。四種手法可以混用。

① 下對搜尋語法

關鍵字＋篩選條件，把幾萬筆結果縮到幾十筆（見下表與第 6 頁）

② 逛主題與整理清單

github.com/topics/civic-tech；搜「awesome＋主題」，找別人整理好的推薦清單

③ 順著組織與人找

用中文描述需求，請 AI 推薦候選專案和搜尋語法，再回 GitHub 查證（第 10 頁）

07三種「拿回來」的方式

Releases 下載

右側 Releases → 選最新版 → Assets 底下下載安裝檔或壓縮檔

最適合：直接要用軟體

Download ZIP

在 Code 分頁按綠色「Code」按鈕 → Download ZIP，取得目前所有檔案

最適合：範本、文件、資料集

Fork

右上角 Fork → 複製到自己帳號，可在線上修改

最適合：想改成自己的版本

單一檔案：點開檔案 → 右上角「Download raw file」圖示。專案沒有 Releases 時，改用 Download ZIP，或看 README 是否有線上版網址。

Tag 與 Release 有什麼不同？有 Tag 不一定有 Release；要下載軟體，看 Releases 就對了

Tag（標籤）Release（發行版）
本質Git 裡指向某次 Commit 的書籤，只有程式碼建在 Tag 上的 GitHub 展示頁，含版本說明（Release Notes）、更新內容與致謝
附加檔案不能夾帶檔案可上傳打包好的安裝檔（.exe、.apk、.zip），不用架開發環境就能下載使用
在哪裡看藏在分支選單的 Tags 分頁或 Git 紀錄裡Repo 首頁右側 Releases，最顯眼
資安提醒：只從可信任、星數與維護狀況良好的專案下載執行檔；下載後用防毒軟體掃描。

09這些東西，不要放上 GitHub

類別例子為什麼
個資會員、志工、捐款人名單，個案資料，身分證字號、電話、地址Public 全世界看得到；Private 也可能因加錯協作者或誤設公開而外流
密碼與金鑰帳號密碼、API Key、Token、.env 設定檔有機器人隨時在掃描 GitHub，幾分鐘內就可能被盜用
內部文件合約、財報草稿、補助申請書、內部會議紀錄一公開就收不回來
沒有權利的素材別人的照片、付費圖庫、字型、新聞全文侵犯著作權，會被要求下架
大檔案影片、大量照片網頁上傳單檔上限 25MB；GitHub 不是雲端硬碟
刪掉不等於消失：Commit 歷史會留著舊版，別人也可能已經 Fork 走。傳錯了先換密碼、換金鑰，再處理檔案。Private Repo 適合放內部草稿，但不是保險箱，個資還是不要放。

GitHub 使用規範禁止的行為違反者可能被隱藏內容、停用 Repo 或停權

冒充他人假冒其他人、組織或品牌開帳號、發內容
騷擾與洗版在 Issue、討論區攻擊他人、重複張貼、打廣告
惡意或違法內容病毒、釣魚網頁、侵權檔案、違法內容
灌星與假帳號買 Star、用多個帳號互刷；一人只能有一個免費帳號
當成檔案分享站拿 GitHub 放影音、大量下載檔給大眾取用

10手法④ 運用 AI 找資源：三種幫手，各管一段

站內問

GitHub Copilot Chat

GitHub 網頁內建，免費方案有每月對話額度，可針對眼前的專案提問

提示詞範本：說清楚「誰、要做什麼、限制」（可直接複製）

我是台灣一個 [組織類型，例：社區環保協會] 的成員，不會寫程式。

我們想要 [需求，例：讓志工線上排班、自動寄提醒]。

請推薦 3–5 個 GitHub 上的開源專案，條件：近一年有更新、授權允許非營利使用、有中文或容易安裝。

每個請附：專案網址、用途一句話、授權、優缺點，以及我可以在 GitHub 搜尋框輸入的搜尋語法。

11帶走這五件事

  1. Repo 是專案資料夾，先讀 README 再決定
  2. 搜尋用英文關鍵字＋topic、stars、pushed、license 篩選
